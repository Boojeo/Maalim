## Read this first (caveats)

1. Router labels are **drafts without a Sharia reviewer** (`status: draft_pending_review`). The 30 seed cases come from the starter pack; the extra cases (ids 101+) were written by the implementer **who also wrote the rules**, so they are not an independent test. Numbers below are a regression check, not a generalisation estimate.
2. The only generalisation signal we have: 25 unseen paraphrases (ids 201+) were probed against the first version of the rules, and **5 of 25 (20%) were wrong** (all in the unsafe direction: answered instead of referred). The rules were then fixed and those cases kept as regressions. Independent cases from the Sharia reviewer are needed for a fair number.
3. The explainer checks run on the **synthetic fixture content** (`tests/fixtures/content`, obviously fake text), because the real `content/passages.json` has no verified passages yet (table below). They say nothing about religious accuracy.
4. The guard threshold was raised from 60 % to 90 % **after** the first stress run let 2 of 13 subtle additions through, so the 13/13 below is a tuned regression result, not an out-of-sample one.
5. Cost and latency are only meaningful with a real adapter.

## Reproduce

```
npm install
npm run eval            # router x3, explainer x3, writes EVAL.md and eval/results/latest.json
npm run eval -- --runs 5
```

To evaluate a real model set `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL` (and optionally `LLM_API_STYLE`, `LLM_PRICE_IN_PER_MTOK`, `LLM_PRICE_OUT_PER_MTOK`) and, for embeddings, `EMBEDDING_PROVIDER`, `EMBEDDING_API_KEY`. Without them the mock adapters are used and this file says so at the top.
